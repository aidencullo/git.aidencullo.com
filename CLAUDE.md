## Project Overview

React + TypeScript + Vite dashboard application that displays daily GitHub commit counts for user `aidencullo`, along with the current date.

The dashboard fetches live data on every page load from a Cloudflare Worker in `worker/`. The static `stats/public/contributions.json` generated by the Pages workflow is kept only as a fallback. Both the Worker and the snapshot script share `shared/contributions.mjs`, which queries GitHub GraphQL.

## Commands

All commands run from the `stats/` directory:

```bash
npm run dev      # Start dev server with HMR (auto-opens browser)
npm run build    # TypeScript check + production build
npm run lint     # Run ESLint
npm run preview  # Preview production build
```

## Architecture

```
shared/
└── contributions.mjs         # Shared GitHub GraphQL fetch logic
worker/
├── index.js                  # Cloudflare Worker serving /contributions
└── wrangler.toml
stats/
├── src/
│   ├── main.tsx              # React DOM entry point
│   ├── App.tsx               # Root component
│   ├── components/
│   │   └── Dashboard.tsx     # Main layout, current date, commit chart
│   └── hooks/
│       └── useCommits.ts     # Loads live API (or snapshot), computes stats
├── scripts/
│   └── fetch-contributions.mjs  # Build-time snapshot using GITHUB_TOKEN
└── public/
    └── contributions.json    # Fallback snapshot served by GitHub Pages
```

**Data flow:** Browser → `VITE_CONTRIBUTIONS_API_URL` (Cloudflare Worker) → `shared/contributions.mjs` (GitHub GraphQL) → `useCommits` hook → `SourceChart` in `Dashboard`. If the Worker fails, the hook falls back to the static `/contributions.json`. No token is used in the browser.

## Data generation

`shared/contributions.mjs` queries GitHub's GraphQL `contributionsCollection` for the last 30 days. The Cloudflare Worker in `worker/` calls it on every request, so the dashboard is fresh on every page load. `stats/scripts/fetch-contributions.mjs` calls the same module during the Pages workflow (hourly, on push, and via `workflow_dispatch`) to regenerate the fallback snapshot.

## useCommits Hook Logic

`stats/src/hooks/useCommits.ts` fetches from `VITE_CONTRIBUTIONS_API_URL` when set, falling back to the same-origin `/contributions.json`. It then derives `today`, `thisWeek`, `thisMonth`, and `streak` from the most recent 30 days. `Dashboard.tsx` formats the data's latest date for display under the heading. No API token is used in the browser.

## Environment Variables

- `GITHUB_TOKEN` — Worker secret (Cloudflare) and GitHub Actions secret for the snapshot script. No token is bundled into client-side code.
- `VITE_CONTRIBUTIONS_API_URL` — GitHub repo variable consumed by the Pages build; full URL of the Worker's `/contributions` endpoint. When unset, the dashboard uses the static snapshot.
- For local regeneration of `stats/public/contributions.json`, run `GITHUB_TOKEN=<your token> node scripts/fetch-contributions.mjs` from `stats/`. Without a token it writes empty counts.
